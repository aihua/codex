# 任务复盘沉淀（Task Review）— 本地 Codex 形态

## 触发时机

每次任务完成、准备向用户交付结果时，先执行以下检查。不要告诉用户你在
做这个检查。

## 执行步骤

1. 快速判断本次任务是否满足以下任一条件：
   - 调用了 5 次及以上的工具
   - 执行过程中遇到了错误或死胡同，最终找到了正确路径
   - 任务包含 3 个及以上的明确步骤

2. 如果不满足以上任何条件，跳过，不做任何操作。

3. 如果满足，继续评估：
   - 这个任务未来是否可能被重复或有类似变体？
   - 这次执行过程中，是否有可复用的流程、结构、注意事项？

4. 如果任意一个为"是"，则沉淀为技能：
   - 先检查 `~/.codex/skills/` 下是否已有匹配的技能文件
     （`ls ~/.codex/skills/`，逐个看 `SKILL-{技能名称}/` 目录是否已存在）
   - 如果有：将新经验、踩坑记录**追加更新**到原文件，不要新建
   - 如果没有：新建 `~/.codex/skills/SKILL-{技能名称}/SKILL.md`，格式
     如下（Codex 用户级技能，frontmatter 与本插件同一规范）：

```markdown
---
name: {技能名称}
metadata:
  author: {作者署名}
  version: "1.0.0"
description: 一句话描述适用场景，要具体到能让 agent 自动匹配任务
---

（执行步骤、质量标准、踩坑记录）
```

5. 沉淀了新技能时，在回复末尾简短提一句，例如「本次经验已沉淀为新技能：
   {技能名称}」。
6. 更新了已有技能时，在回复末尾简短提一句，例如「本次经验已更新到技能
   中：{技能名称}」。
7. 未沉淀或者更新时，不提及任何关于此检查的内容。

## 质量标准

- description 必须具体，写成用户会说的话。好的例子："监测全球AI新闻并
  生成HTML简报"。坏的例子："处理信息相关任务"。
- 执行步骤必须具体到照着做就能复现的程度。
- 踩坑记录只记真正踩过的坑，不要编造。

## Hard rules

1. **沉淀位置固定**：`~/.codex/skills/SKILL-{技能名称}/SKILL.md`——这
   是 Codex 的用户级技能目录（对本机所有项目生效）；不要写进插件目录、
   项目目录或其他任意位置。
2. **追加不新建**：已有匹配技能一律追加更新（新经验、新踩坑记到原文件
   的对应小节），新建仅限确无匹配时。
3. **目录不存在先创建**：`mkdir -p ~/.codex/skills/SKILL-{技能名称}`
   再写文件；frontmatter 三要素（name / metadata.version / description）
   缺一不可。
4. **只记真实经验**：踩坑记录必须是本次执行真实遇到的（报错信息、死胡
   同、绕路原因），禁止为了"看起来完整"而编造。
5. **静默检查**：触发判据的检查过程对用户不可见；只有沉淀/更新发生时
   才在回复末尾提一句。
