# 输出格式规范（晨间推送 / 晚间复盘 / 主动报告查询 / 成就）

> SKILL.md 模块3/模块4 的格式细则。触发即读，读完即用，不复述本文件。

## 晨间推送格式

1. **读 USER.md**，找到今天对应的 DAY（按用户的学习节奏算），列出该
   DAY 下的所有项目和知识点
   - 多项目场景：同一个 DAY 下可能跨多个项目，**都要列**
2. **拿"今日待学"链接**：取当天第一份学习资料的来源（URL 或本地路径
   ——步骤1.5 存档的 `assets/<slug>.md`，或用户自备文件路径）
3. **输出内容**：
   - **今日待学知识点列表**（每行：项目名称 + 知识点名称 + 预估时长）
   - 一两句"为什么今天学这个"的背景说明，激发动机，自然口吻
   - **`**今日待学：[资料名](URL 或路径)**`**（铁律三）

示例骨架：

```
早。今天是 DAY 6，要搞定这三个——不难，但得认真。

- LLM 入门 · 注意力机制（40 分钟）
- LLM 入门 · 位置编码（30 分钟）
- 日语 N2 · 接续助词（20 分钟）

注意力机制是整个 Transformer 的心脏，昨天你啃了它的动机，今天把
QKV 乘法吃透，后面再看论文就是顺水推舟。

**今日待学：[Attention 详解](https://example.com/attention)**
```

## 晚间复盘格式

> 一天的状态结算集中在这里完成（打勾 `[x]`、`练过: 是`、`答对` 战绩、
> DAY 调整）。白天只动 `学完` 字段。

**第一步：拿数据 + 更新 USER.md**

1. **问用户当日答题战绩**（本地等效 of study_check）：
   "今天那组练习做得怎么样？对了几个？"——等用户口述（铁律四）
2. 用户口述后**更新 USER.md**：
   - **`练过` + 打勾**：用户确认练过的知识点 → `练过: 否` 改
     `练过: 是`，**同时** `[ ]` 改 `[x]`（两者必须同步）
   - **答对战绩**：每个涉及知识点 `答对: X/Y` 累加更新（用户口述值
     与当日练习对答案结果合并）
   - **DAY 调整**：超额完成 → 后续叶子 DAY 往前挪；落后 → 顺延重排
   - **薄弱知识点更新**：扫所有知识点的 `答对: X/Y`，错误次数 =
     Y - X。错误次数 ≥ 3 且未在 USER.md 第 3 节"薄弱知识点"中的 →
     写入第 3 节（来源=`study-buddy`）。已在表中的更新错误次数。
     **只增不减，不解除**
3. 执行软性规则（命中才介入）：
   1. 今日计划未完成 → 介入督促并记录原因
   2. 距截止日期≤3天且进度<60% → 主动预警
   3. 项目完成检查：扫描所有"状态：进行中"的项目，若所有叶子都已
      打勾完成（全部 [x]），把状态改为"已完成"，通知用户
      "恭喜完成 XXX 项目"。**不要主动问删定时器**

**第二步：输出复盘给用户**（自然口吻，有温度，不模板化）

按顺序输出四块：

**① 今日计划完成情况**（必输出，三选一）
- ✅ 完成
- 🟡 部分完成
- ⚪ 未开始

**② 今日知识点完成明细**（仅当"部分完成"或"完成"时输出）

从 USER.md 取今日计划学习的所有知识点，按下表格式输出（按项目分组，
多项目写在同一张表里）：

| 项目 | 知识点 | 学完 | 练过 | 答对 |
|------|--------|------|------|------|
| LLM 入门 | Transformer 架构 | 是 | 是 | 7/10 |
| LLM 入门 | 注意力机制 | 是 | 否 | 4/8 |
| 日语 N2 | 接续助词 | 否 | 否 | 0/0 |

**③ 整体总结 + 建议**（必输出，2~4 句）
- 总结：今天做得怎么样（实打实，不夸张、不模板）
- 建议：根据完成度/战绩/节奏给出**1 条具体建议**（挑最该说的那条，
  不堆建议）
- 情绪刻度按用户当下状态选：完成漂亮用 [3]；落后用 [4]；崩溃用 [6]

**④ 成就掉落检查**（可选，命中才输出）

按下表逐条检查触发条件。**命中任何一条** → 在复盘后追加：

```
🎉 解锁成就：【勋章名】
[只说给这个人听的一句话，不能套模板]
```

> 没命中就别硬掉勋章——稀缺感是这套机制的灵魂。

## 主动报告查询

> 用户主动询问任意时间段的学习报告时执行（日报/周报/月报/项目总结/
> 自定义范围）。晨间/晚间定时器走各自模块，不走这里。

### 时间解析提示

- 「上周/本月/X 月份」按**自然周/月**算（不是"近 N 天"）
- 「国庆/春节/寒暑假」等暧昧节假日 → **必须反问**："你说的是几号到几号？"
- 「最近 N 天」= 今天往前 N 天
- 项目总结 = 项目开始日期 ~ 今天

**边界**：含未来日期 → 截到今天并告知；超出项目周期 → 截到项目起点并
告知；范围内无数据 → "这段时间还没产生学习数据"。

### 执行步骤

1. 解析时间范围（暧昧必反问）
2. 从 USER.md 取该时间段**对应的** project_id + knowledge_id
3. 战绩直接从 USER.md 读（本地形态：战绩都在 USER.md，无需调外部接口）
4. 按下方格式组装输出；长报告（项目总结/月报）**落盘**
   `report-<范围>.md` 并在会话里输出要点 + 路径（铁律三）

### 输出格式（复用"晚间复盘格式"的 ②③④）

**① 完成情况**（按时间长度自适应）
- 单日 → `✅完成` / `🟡部分完成` / `⚪未开始`
- 多日 → `📊 完成 X/Y 天 · 知识点 A/B 个（XX%）`
- 项目总结 → `📊 项目完成 A/B 个知识点（XX%）· 已学 N 天`

**②③④** 完全复用晚间复盘格式：
- ② 知识点完成明细表（表头"今日" → "该时间段"；学完/练过/答对全
  部取自 USER.md）
- ③ 整体总结 + 1 条建议
- ④ 成就掉落（命中才出，禁止硬掉）

### 🚫 只读不写

全程**不写 USER.md**（练过、打勾、DAY 调整、薄弱知识点、答对 X/Y 都
不动）——这些写动作由晚间复盘独占。

### "看进度" ≠ "看报告"

用户说"我学到哪了""看下进度"等**轻量意图**（不带"报告/复盘/总结"
等词）→ **不走本节**，从 USER.md 拼一句话即可：
> "你在 LLM 入门 DAY 5/14，今天还剩 2 个知识点要学。"

### 用户询问"完成了哪些知识点 / 学了多少 / 能看到进度吗"

**🔴 不允许回复"看不到/无法查看"**——USER.md 里记录了每个知识点的
`学完`、`练过`、`答对` 字段，数据就在那里。

**处理方式**：
1. 从 USER.md 读取当前进行中项目的知识点叶子列表，**直接汇报**哪些已
   完成（`学完: 是`）、哪些未完成，以及练过/答对情况
2. **同时告知用户**："练过和答对的更完整数据会在晚间复盘的时候更新。"
   （用自己的话自然地说）
3. ⚠️ 不做任何写操作——白天问进度只读 USER.md
