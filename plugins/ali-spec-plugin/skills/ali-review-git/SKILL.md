# Git 规约评审

对 提交信息（Commit Message）、分支与标签命名 执行 ali-git-spec 所载规约的逐条走查，输出带规则编号与严重级（P0/P1/P2）的违规清单与修复建议。本技能不复制规则，规则全文以 ali-git-spec 的 references 为单一事实源。

## 评审流程（五步）

1. 确定范围：用户给文件路径则读取文件；给代码片段则直接评审；两者皆无则先询问要评审的对象。
2. 加载规则：读取 ../ali-git-spec/references/ 下相关规则文件全文（按下方「规则来源」选择章节）；涉及前后端接口契约时加读 ../../shared-references/http-json-api.md。样式与缩进类问题同时加读 ../../shared-references/common.md（等级按语言规约裁决，见该文件编者注）。
3. 逐条比对：按速查索引九个要点逐条检查：提交消息（格式/语言/类型/正文脚注）、工作流、分支（常驻/临时）、标签（版本号/前缀）；与本次变更无关的范围可跳过，但不得遗漏已涉及范围。
4. 定位引用：每处违规给出规则编号、等级、原文依据（引用规则关键原文，不凭空发挥）。
5. 输出报告：按下方「输出报告模板」输出，并附修复建议与统计结论。

## 规则来源（跨目录引用，单一事实源）

| 文件 | 内容 | 加载时机 |
| --- | --- | --- |
| ../ali-git-spec/references/01-提交消息.md | 提交消息/Commit Message（格式、语言、类型、范围、正文、脚注）（规则条目 0） | 按评审对象涉及范围选择 |
| ../ali-git-spec/references/02-工作流与分支标签命名.md | 工作流 + 分支命名 + 标签命名 + 参考资料（规则条目 0） | 按评审对象涉及范围选择 |
| ../ali-git-spec/SKILL.md | 规则速查索引（编号 → 摘要 → 全文位置） | 定位规则编号时 |
| ../../shared-references/common.md | 通用编码规约（2 空格缩进、行宽 100、UTF-8） | 涉及通用代码风格时；等级以语言规约为准 |
| ../../shared-references/http-json-api.md | HTTP JSON API 规范（响应信封、分页协议、排序参数） | 评审对象涉及 API 设计或接口字段时 |

## 严重级映射

- 源文档等级「强制」→ P0 阻断：必须修复后才能提交。
- 源文档等级「推荐」→ P1 警告：强烈建议本次修复。
- 源文档等级「参考」→ P2 提示：视情况选择，报告末尾汇总即可。
- 共享参考 common.md 的等级裁决：同一规则语言规约已有等级的以语言规约为准（如 CSS/HTML 缩进按「推荐」→ P1）。

## 输出报告模板

评审报告以 Markdown 表格输出，字段固定（多次评审结果可比较、可归档）：

| 位置 | 规则编号 | 等级 | 违规说明 | 修复建议 |
| --- | --- | --- | --- | --- |
| （文件名:行号 或 片段序号） | （源规约编号，可溯源） | （P0/P1/P2） | （违反了哪条规则，引用规则关键原文） | （给出符合规约的具体改法） |

报告尾注必含四项：

1. 统计：P0 / P1 / P2 各多少处。
2. 结论：是否存在 P0（存在则明确「阻断提交」，修复后可申请复审）。
3. 覆盖：本次走查覆盖的规则范围（如「建表 15 条 + 索引 11 条」），未覆盖范围说明原因。
4. 依据版本：规则来源与版本（手册终极版 1.3.0 / f2e-spec 对应规约）。

## 与规约技能的分工

- 编码/写文档场景 → ali-git-spec（先读规则再动手）。
- 评审/走查场景 → 本技能（ali-review-git，五步流程 + 标准化报告）。
- 典型评审对象：提交信息格式与 type/scope 取值、工作流选型、分支命名、标签与语义化版本。
